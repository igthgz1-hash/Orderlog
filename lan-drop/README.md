# LAN Drop — ส่งไฟล์ระหว่างมือถือกับ PC ผ่านเว็บเบราว์เซอร์ (สองทาง)

ทางเลือกที่ **ทำงานได้แน่นอน** แทนการเลียนแบบโปรโตคอล AirDrop (ดู `../airdrop-tool/`
ซึ่งยังติดปัญหา BLE discovery ที่ Apple ไม่เปิดเผยสเปก) — วิธีนี้ใช้แค่ HTTP ธรรมดา
กับหน้าเว็บเดียว ใช้ได้กับมือถือทุกยี่ห้อ (iPhone, Samsung, Android อื่นๆ) โดยไม่ต้อง
ติดตั้งแอปเพิ่ม ส่งไฟล์ได้ทั้งสองทาง:

- **มือถือ → PC**: อัปโหลดผ่านฟอร์มบนหน้าเว็บ
- **PC → มือถือ**: เอาไฟล์ไปวางในโฟลเดอร์ที่กำหนด (`--send-dir`) แล้วมันจะขึ้นเป็น
  ลิงก์ดาวน์โหลดบนหน้าเว็บเดียวกันให้มือถือแตะโหลดได้เลย

## ติดตั้งแบบไวสุด — ดับเบิลคลิกเดียวจบทุกครั้ง (Windows)

โหลด **[`dist/Sevastopol File Transfer v1.exe`](dist/Sevastopol%20File%20Transfer%20v1.exe)**
แล้วดับเบิลคลิกได้เลย — ไฟล์เดียวใช้ได้ทั้ง "ติดตั้งครั้งแรก" และ "รันโปรแกรมทุกวัน"
ต่อจากนี้:

- **ครั้งแรกที่รันบนเครื่องนั้น**: จะขึ้นหน้าต่างขออนุญาต Administrator (UAC) แล้ว
  ติดตั้งทุกอย่างให้อัตโนมัติ (สร้าง venv, ลง dependency, เปิดพอร์ตไฟร์วอลล์, สร้าง
  shortcut บน Desktop) จากนั้น**เปิดโปรแกรมขึ้นมาทำงานทันที** — ไม่ต้องเปิด PowerShell
  หรือพิมพ์คำสั่งใดๆเองเลย
- **รันครั้งต่อๆไป (เครื่องเดิม)**: ข้ามขั้นตอนติดตั้งไปเลย เปิดโปรแกรมทำงานทันที
  (ยังต้องกด UAC ทุกครั้ง เพราะ Windows ผูกสิทธิ์ admin ไว้กับทั้งตัวโปรแกรม)
- **เอาไปรันที่เครื่อง Windows อื่น**: ก็อบไฟล์ .exe ไฟล์เดียวไปวางแล้วดับเบิลคลิกได้
  เลย จะติดตั้งให้ใหม่อัตโนมัติเหมือนครั้งแรก
- **เปิด Google Drive backup ในเครื่องอื่นแบบไม่ต้องพิมพ์คำสั่งเอง**: ก็อบไฟล์
  `credentials.json` (จากขั้นตอนใน "Google Drive backup" ด้านล่าง) ไปวาง**ไว้ในโฟลเดอร์
  เดียวกันกับตัว .exe** ก่อนดับเบิลคลิก — ตัวติดตั้งจะเจอไฟล์นี้แล้วก็อบปี้เข้าตำแหน่งที่
  ถูกต้อง (`%LOCALAPPDATA%\LanDrop\credentials.json`) ให้อัตโนมัติ ไม่ต้องเข้าไปวางเอง
  ในโฟลเดอร์ที่ซ่อนอยู่นั้น (ยังต้องล็อกอินเบราว์เซอร์หนึ่งครั้งต่อเครื่องเหมือนเดิม —
  ดูหัวข้อด้านล่าง)

**ไม่ต้องมี Python 3 มาก่อนแล้ว**: ถ้าเครื่องนั้นยังไม่มี Python 3 ตัวติดตั้งจะ
**โหลดตัวติดตั้ง Python 3 ตัวจริงจาก python.org แล้วติดตั้งให้อัตโนมัติ** (เงียบๆ ไม่ขึ้น
หน้าต่างถามอะไรเพิ่ม) ก่อนติดตั้ง LAN Drop เอง — ยังคงเป็นดับเบิลคลิกเดียวจบเหมือนเดิม
แต่ขั้นตอนนี้ต้องมีอินเทอร์เน็ตตอนรันครั้งแรก (ถ้าโหลดไม่สำเร็จ เช่น ไม่มีเน็ต จะถามว่า
จะเปิดหน้าเว็บให้โหลดเองแทนไหม)

ถ้าโค้ดใน `server.py` มีการอัปเดต ต้องสร้างไฟล์ .exe ใหม่ด้วยคำสั่ง
`./build_installer.sh` (ต้องมี NSIS ติดตั้งไว้ — ดู `installer.nsi`)

> **หมายเหตุความมั่นใจ**: ตัว `.exe` นี้คอมไพล์และตรวจสอบโครงสร้างไฟล์ภายใน
> (ยืนยันว่าเป็น PE executable ของ Windows ที่ถูกต้อง และไฟล์ที่บรรจุไว้ข้างในครบ)
> แต่ยังไม่เคยรันทดสอบจริงบนเครื่อง Windows เพราะ session นี้ไม่มีฮาร์ดแวร์ Windows
> ให้ทดสอบ — ตัวมันเรียกใช้ `install.ps1` ตัวเดียวกับที่ทดสอบผ่านบนเครื่องจริงมาแล้ว
> ก่อนหน้านี้ในโปรเจกต์ ส่วนฟีเจอร์ที่เพิ่มใหม่ล่าสุด (ดาวน์โหลด+ติดตั้ง Python 3 ให้
> อัตโนมัติผ่าน `NSISdl`, การก็อบปี้ `credentials.json` จากข้างๆตัว .exe, และการสลับไปใช้
> `py -3` launcher ตอน `python` ยังไม่ขึ้น PATH ในรอบเดียวกัน) **ยังไม่เคยรันจริงบนเครื่อง
> Windows เช่นกัน** เพราะ session นี้ไม่มีเน็ตออกไปที่ python.org ให้ทดสอบการดาวน์โหลดจริง
> (ตรวจสอบแค่ว่า NSIS compile ผ่านไม่มี syntax error) — ควรลองรันจริงครั้งแรกบนเครื่องที่
> ยังไม่มี Python 3 แล้วดูผลด้วย

## ติดตั้งแบบสคริปต์ (ทางเลือกสำรอง)

**Windows:** เปิด PowerShell **แบบ Administrator** แล้วรัน (จำเป็นต้องเป็น Admin
เพื่อเปิดพอร์ตในไฟร์วอลล์ให้อัตโนมัติ):
```powershell
cd lan-drop
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
.\install.ps1
```
จะได้ shortcut ชื่อ "Sevastopol File Transfer" บนหน้า Desktop ไว้ดับเบิลคลิกเปิดใช้งาน
ได้เลยทุกครั้ง โดยไม่ต้องเปิด PowerShell/พิมพ์คำสั่งอีก (ถอนการติดตั้งด้วย
`.\uninstall.ps1`) — นี่คือสคริปต์ตัวเดียวกับที่ `Sevastopol File Transfer v1.exe`
เรียกใช้ข้างในนั่นเอง แค่ต้องเปิด PowerShell เองแทนการดับเบิลคลิก

**macOS / Linux:**
```bash
cd lan-drop
./install.sh
```
จะได้คำสั่ง `lan-drop` ไว้เรียกใช้ได้จากเทอร์มินัล

## วิธีใช้แบบรันเอง (ไม่ผ่านตัวติดตั้ง)

```bash
cd lan-drop
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python3 server.py --name "PC ของฉัน" --out-dir ~/Downloads/LanDrop
```

จะเห็น QR code แสดงในเทอร์มินัลทันที:

### ส่งจากมือถือไป PC

1. เอามือถือ (ต้องต่อ **Wi-Fi วงเดียวกัน** กับ PC) สแกน QR code นั้น หรือพิมพ์ URL
   ที่แสดงไว้ (เช่น `http://192.168.1.74:8000/`) ในเบราว์เซอร์เอง
2. หน้าเว็บจะเปิดขึ้นมาพร้อมฟอร์มเลือกไฟล์ — เลือกรูป/ไฟล์ที่ต้องการส่ง (เลือกได้
   หลายไฟล์พร้อมกัน) แล้วกด "ส่งไฟล์"
3. ไฟล์จะถูกบันทึกลง `--out-dir` ที่ตั้งไว้ทันที (ค่าเริ่มต้น `~/LanDropReceived`) และ
   ขึ้นในรายการ "ไฟล์ที่ได้รับแล้ว" บนหน้าเว็บให้เห็นว่าส่งสำเร็จ

### ส่งจาก PC ไปมือถือ

1. เอาไฟล์ที่จะส่งไปวางไว้ในโฟลเดอร์ `--send-dir` (ค่าเริ่มต้น `~/LanDropToSend` —
   สร้างให้อัตโนมัติตอนเริ่มรัน)
2. ที่มือถือ เปิด URL เดิม (หน้าเดียวกับตอนส่งไฟล์เข้า) จะเห็นหัวข้อ "ไฟล์จาก PC
   (แตะเพื่อดาวน์โหลด)" พร้อมรายชื่อไฟล์ทั้งหมดในโฟลเดอร์นั้น
3. แตะชื่อไฟล์เพื่อดาวน์โหลด — รูปภาพจะเปิดในเบราว์เซอร์ให้กดค้าง (long-press) เพื่อ
   บันทึกลง Photos ได้เลย ส่วนไฟล์ประเภทอื่น (เอกสาร, zip ฯลฯ) จะดาวน์โหลดเข้า Files
   app โดยตรง

## Google Drive backup (ทางเลือกเสริม)

เปิดใช้ได้เพื่อให้ทุกไฟล์ที่มือถือส่งเข้ามา **ถูกอัปโหลดสำรองขึ้น Google Drive
อัตโนมัติ** (ทำงานเบื้องหลัง ไม่ทำให้การอัปโหลดช้าลง) — ต้องตั้งค่าครั้งเดียวก่อน:

**ขั้นตอนตั้งค่า (ทำครั้งเดียว):**

1. ไปที่ [Google Cloud Console](https://console.cloud.google.com/) → สร้างโปรเจกต์ใหม่
   (หรือใช้โปรเจกต์เดิม)
2. ไปที่ **APIs & Services → Library** → ค้นหา "Google Drive API" → กด **Enable**
3. ไปที่ **APIs & Services → OAuth consent screen** → ตั้งค่าเบื้องต้น (เลือก
   "External" ถ้าถาม, ใส่ชื่อแอปอะไรก็ได้ เช่น "LAN Drop") → เพิ่มอีเมลของคุณ
   (`igthgz1@gmail.com`) เป็น Test user
4. ไปที่ **APIs & Services → Credentials** → **Create Credentials → OAuth client ID**
   → เลือกประเภท **Desktop app** → ตั้งชื่ออะไรก็ได้ → กด Create
5. กด **Download JSON** จากที่สร้างเสร็จ แล้วเปลี่ยนชื่อไฟล์เป็น `credentials.json`
   วางไว้ในโฟลเดอร์ `lan-drop/` (**ห้าม commit ไฟล์นี้เข้า git** — มี `.gitignore`
   กันไว้ให้แล้ว)

> **ใช้กับ `Sevastopol File Transfer v1.exe` หลายเครื่อง**: วางไฟล์
> `credentials.json` ไว้ในโฟลเดอร์เดียวกันกับตัว .exe บนเครื่องนั้นๆ ก่อนดับเบิลคลิก
> ตัวติดตั้งจะก็อบปี้ให้เข้าตำแหน่งที่ถูกต้องเองอัตโนมัติ (ดูหัวข้อ "ติดตั้งแบบไวสุด"
> ด้านบน) — ไม่ได้ฝังไฟล์นี้ไว้ในตัว .exe เอง เพราะ `credentials.json` คือ OAuth client
> secret ส่วนตัวของบัญชี Google Cloud ของคุณ ถ้าฝังไว้ในตัว .exe แล้วเอาไฟล์นั้นไปแจก/
> อัปโหลดที่อื่น คนอื่นที่ได้ไฟล์ .exe ไปก็จะได้ secret นี้ไปด้วย (แต่เพราะหน้า OAuth
> consent screen ตอนนี้อยู่ในสถานะ "Testing" คนที่ไม่ได้อยู่ใน Test user list จะล็อกอิน
> ผ่านไม่ได้อยู่ดี — ความเสี่ยงจึงต่ำถ้าไม่แจก .exe ที่มี credentials.json อยู่ข้างๆ
> ให้คนอื่นแบบไม่ระวัง)

**การใช้งาน:**

```bash
pip install -r requirements-drive.txt
python3 server.py --name "PC ของฉัน" --backup-to-drive
```

รันครั้งแรกจะเปิดเบราว์เซอร์ให้ล็อกอินและกดยอมรับสิทธิ์เข้าถึง (ต้องล็อกอินด้วย
บัญชี Google ที่ต้องการให้เป็นที่เก็บไฟล์สำรอง เช่น `igthgz1@gmail.com`) — หลังจากนั้น
จะมีไฟล์ `token.json` ถูกสร้างไว้ในโฟลเดอร์เดียวกัน (**ห้าม commit เช่นกัน**) ให้ใช้
ล็อกอินอัตโนมัติในรันครั้งต่อๆไป ไม่ต้องเปิดเบราว์เซอร์อีก

ไฟล์จะถูกอัปโหลดไปไว้ใต้โฟลเดอร์ชื่อ **"LAN Drop Backups"** บน Drive (เปลี่ยนชื่อ
โฟลเดอร์หลักได้ด้วย `--drive-folder`) แยกเป็น 2 โฟลเดอร์ย่อยตามทิศทาง:

```
LAN Drop Backups/
├── Received/   <- ไฟล์ที่มือถือส่งเข้า PC (ลง --out-dir)
└── Sent/       <- ไฟล์ที่ PC ส่งให้มือถือ (ดาวน์โหลดจาก --send-dir)
```

**ลบไฟล์ในเครื่องอัตโนมัติหลัง backup สำเร็จ (เฉพาะ Received, ค่าเริ่มต้น)**: เพื่อ
ประหยัดพื้นที่ดิสก์ พอไฟล์ที่**มือถือส่งเข้ามา**ถูกอัปโหลดขึ้น Drive สำเร็จแล้ว
**ไฟล์ในเครื่อง (`--out-dir`) จะถูกลบทิ้งทันที** (ไฟล์จะหายจากรายการ "ไฟล์ที่ได้รับแล้ว"
บนหน้าเว็บหลังจากนั้น เพราะย้ายไปอยู่บน Drive แทน) — ถ้า backup ล้มเหลว (เช่น ไม่มีเน็ต)
ไฟล์ในเครื่อง **จะไม่ถูกลบ** เพื่อไม่ให้ข้อมูลหาย ถ้าต้องการเก็บสำเนาไว้ในเครื่องด้วย
ใส่ `--keep-local-copy`

ส่วนไฟล์ฝั่ง **Sent** (ใน `--send-dir`) จะสำรองขึ้น Drive ด้วยเช่นกันตอนมือถือดาวน์โหลด
จริง แต่**จะไม่ถูกลบออกจากเครื่อง** เพราะเป็นไฟล์ต้นทางที่ PC อาจต้องใช้ส่งซ้ำให้มือถือ
เครื่องอื่นอีก และจะสำรองแค่ครั้งแรกที่ดาวน์โหลดในแต่ละรอบที่เปิดโปรแกรม (ไม่อัปโหลดซ้ำ
ทุกครั้งที่มีคนโหลดไฟล์เดิม)

**ขอบเขตสิทธิ์**: ใช้ scope `drive.file` เท่านั้น — แอปนี้มองเห็น/แก้ไขได้แค่ไฟล์ที่
มันสร้างขึ้นเอง เข้าไม่ถึงไฟล์อื่นๆ ใน Drive ของคุณเลย

**ทดสอบแล้วในเครื่อง**: logic การหา/สร้างโฟลเดอร์, การอัปโหลด, และการลบไฟล์หลัง
backup สำเร็จ ผ่านการทดสอบด้วย mock ครบทั้ง 3 กรณี — ลบไฟล์จริงเมื่อสำเร็จ, ไม่ลบเมื่อ
ใส่ `--keep-local-copy`, และไม่ลบเมื่อ backup ล้มเหลว (ป้องกันข้อมูลหาย) แต่
**ยังไม่เคยรันผ่าน OAuth flow จริงกับบัญชี Google จริง** เพราะ session นี้ไม่มี
เบราว์เซอร์แบบ interactive ให้ล็อกอิน — ต้องลองรันจริงครั้งแรกแล้วดูผลด้วย

## ทำไมถึงมั่นใจว่าใช้ได้จริง

- ใช้ HTTP (ไม่ใช่ HTTPS) ธรรมดา ไม่มี certificate ให้เบราว์เซอร์เตือน
- ฟอร์มอัปโหลดไฟล์เป็นมาตรฐานเว็บพื้นฐาน (`multipart/form-data`) ที่เบราว์เซอร์ทุก
  ยี่ห้อรองรับมานานแล้ว ไม่ต้องอาศัยการเดาโปรโตคอลที่ Apple ไม่เปิดเผย
- ทดสอบแล้วในเครื่อง: อัปโหลดไฟล์ข้อความและไฟล์ binary จำลอง เปรียบเทียบ byte
  ต้นทาง/ปลายทางตรงกัน 100% รวมถึงทดสอบการดาวน์โหลด (ทั้งแบบ inline สำหรับรูปภาพ
  และแบบ attachment สำหรับไฟล์อื่น) และป้องกัน path traversal บน endpoint ดาวน์โหลด

- ต้องอยู่ Wi-Fi เครือข่ายเดียวกันระหว่าง PC กับมือถือ (เหมือน AirDrop ต้องใช้
  Wi-Fi ร่วมกันเช่นกัน ในกรณีที่ไม่ได้ใช้ AWDL)
- ไม่มีการเข้ารหัสระหว่างทาง (plain HTTP) — เหมาะสำหรับใช้ในเครือข่ายบ้าน/ที่ทำงาน
  ที่ไว้ใจได้ ไม่ควรใช้บนเครือข่ายสาธารณะที่ไม่น่าเชื่อถือ
- ไม่มีการยืนยันตัวตนผู้ส่ง (ใครก็ได้ที่อยู่ในเครือข่ายเดียวกันและรู้ URL/สแกน QR
  ได้ ก็ส่งไฟล์เข้ามาได้)

## โครงสร้างไฟล์

- `server.py` — เว็บเซิร์ฟเวอร์ทั้งหมด (หน้าเว็บ + endpoint รับไฟล์ + QR code)
- `dist/Sevastopol File Transfer v1.exe` — ตัวติดตั้ง + เปิดโปรแกรมสำเร็จรูปสำหรับ
  Windows (ดับเบิลคลิกเดียวจบ ทั้งติดตั้งครั้งแรกและรันทุกครั้งถัดไป)
- `installer.nsi` / `build_installer.sh` — source code ของตัว .exe ข้างบน
  (ใช้ NSIS คอมไพล์ — รันใหม่ทุกครั้งที่แก้ `server.py`)
- `install.ps1` / `uninstall.ps1` — ตัวติดตั้ง/ถอนการติดตั้งแบบสคริปต์สำหรับ Windows
  (ตัวเดียวกับที่ `Sevastopol File Transfer v1.exe` เรียกใช้ข้างใน)
- `install.sh` — ตัวติดตั้งสำหรับ macOS/Linux
- `drive_backup.py` — โมดูล backup ไฟล์ขึ้น Google Drive (ทางเลือกเสริม, ดูหัวข้อด้านบน)
- `requirements-drive.txt` — dependency เฉพาะตอนใช้ `--backup-to-drive`
